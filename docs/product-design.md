# URL Parameter Studio — プロダクト設計書

- 状態: 提案（実装前）
- 対象: `url-params-builder` の次期版
- 更新日: 2026-09-23
- 方針: **ログインなしでURLパラメータの作成・解析・検査を完結できる。ログインは、他者・他端末・組織とデータを扱うためだけに使う。**

## 1. プロダクトの再定義

本プロダクトはGA4のUTM作成器ではなく、URLクエリパラメータを安全に設計・生成・検査・共有するための **URL Parameter Studio** である。

対象は、GA4のUTM、Adobe Analyticsの追跡コード（例: `cid`）、広告媒体固有のパラメータ、CRM連携用の値、社内独自パラメータである。どのキーを使うか、どの形式で値を構成するかは組織ごとに異なるため、固定された入力フォームではなく、設定可能な「プロファイル」と「ルール」を中心に設計する。

### 解決する課題

- URLを手入力すると、`?` / `&`、エンコード、既存クエリ、ハッシュ、重複キーで壊れやすい。
- 媒体名・施策名の表記ゆれが、分析レポートを分断する。
- 計測担当者以外には、どのパラメータを使うべきか判断しにくい。
- 共有用スプレッドシートでは、変更履歴、承認、再利用、意図の記録が弱い。
- ただし、単発でURLを作りたい人にアカウント作成を要求すると利用開始の障壁になる。

### 根拠

既存アプリはURL生成・ローカル保存を提供している一方、項目がUTMに固定され、候補もコードに埋め込まれている。Adobe Analyticsでは、追跡コードに用いるクエリキーや値の形式を組織が決めることができるため、固定仕様では対応できない。

## 2. プロダクト原則

1. **匿名ファースト**: URL作成のためにログインを要求しない。
2. **ベンダー非依存**: GA4、Adobe、広告媒体、社内用途を同じデータモデルで扱う。
3. **ルールは設定、URLは成果物**: 組織のルールをコードに埋め込まない。
4. **安全を標準にする**: URL構文、重複、エンコード、個人情報らしき値を作成時に検査する。
5. **説明可能にする**: URLだけでなく、用途・担当者・期限・判断理由を残せる。
6. **ログインは価値の拡張**: ログインしないと基本機能が使えない設計にしない。

## 3. 利用者と利用シナリオ

| 利用者 | 主な目的 | 利用形態 |
|---|---|---|
| 単発利用者 | メール・SNS掲載用のURLを1本作る | 匿名 |
| マーケター | 施策ごとに複数媒体・複数クリエイティブのURLを作る | 匿名またはログイン |
| 計測担当者 | 命名規約と候補を整備し、誤った計測を防ぐ | ログイン＋組織管理者 |
| 制作・代理店 | 決められたルールでURLを生成し、確認依頼を出す | ログイン＋組織メンバー |

## 4. 機能境界：匿名とログイン

### ログイン不要（公開機能）

以下は、ブラウザ内だけで完結し、すべてログインなしで使える。

- URL貼り付け解析、URLパラメータの追加・編集・削除・並び替え
- 任意キー・値によるURL生成、コピー、ダウンロード
- GA4、Adobe、広告、汎用のスタータープロファイル選択
- 既存URLのクエリとハッシュを保った安全なマージ
- URL構文、重複キー、空値、長さ、エンコード、命名規則の検査
- 個人情報らしき値（メールアドレス、電話番号、カード番号形式など）の警告
- キャンペーン・マトリクスによる複数URLの一括生成とCSV入出力
- ブラウザ内の保存、ノート、ローカルのカスタムプロファイル・候補・お気に入り
- 保存データのJSONバックアップ／復元

匿名データは原則として端末のローカルストレージに保存する。ユーザーが明示的に共有・送信しない限り、URL、ノート、入力値をサーバーへ送信しない。

### ログイン後のみ（識別・認可が必要な機能）

| 機能 | ログインが必要な理由 |
|---|---|
| クラウド保存・端末間同期 | 保存先・所有者の識別が必要 |
| 組織ワークスペース | 組織・メンバーの認可が必要 |
| 共有リンク、共同編集、コメント | 誰が閲覧・編集できるか制御が必要 |
| 承認フロー、変更履歴、復元 | 操作者と時刻を監査可能にする必要がある |
| 組織共通のプロファイル・候補マスタ | 管理者だけが変更できる必要がある |
| 個人の設定をクラウドにバックアップ | 所有者と暗号化対象の識別が必要 |

ログインしても、公開機能の操作フローは変えない。ログインは「保存先をクラウドへ」「チームに共有」「組織ルールを適用」という追加の選択肢として提示する。

## 5. 中核コンセプト

### 5.1 パラメータ・プロファイル

プロファイルは、用途ごとのパラメータ定義セットである。

- **スタータープロファイル**: GA4 UTM、Adobe Tracking Code、広告・CRM、空の汎用プロファイル
- **ローカルプロファイル**: 匿名利用者が自端末向けに作成・編集するもの
- **組織プロファイル**: 管理者が配布し、メンバーが利用するもの

プロファイルの各項目には、キー、表示名、説明、必須可否、入力型、候補、初期値、正規化規則、正規表現、機密性、値の組立規則を設定する。

例:

| 項目 | GA4例 | Adobe例 | 独自例 |
|---|---|---|---|
| パラメータキー | `utm_source` | `cid` | `ref_code` |
| 入力方式 | 候補＋自由入力 | 複数要素を結合 | テキスト／選択／日付 |
| 値の規則 | 小文字・`_`区切り | `channel\|yyyymm\|campaign` | 組織が定義 |
| 例 | `newsletter` | `email\|202609\|autumn_sale` | `partner_001` |

### 5.2 URLインスペクター

URLを貼り付けると、URL本体・ハッシュ・クエリを分解して表形式にする。プロファイルに一致するキーは説明・候補・検査を表示し、未知のキーは消さずに「任意パラメータ」として保持する。

### 5.3 キャンペーン・マトリクス

「施策 × 媒体 × クリエイティブ × CTA」の選択肢を入力すると、必要なURLをまとめて生成する。各行には固有のノート・担当者・ステータスを持たせ、CSVで制作会社や広告管理画面に渡せる。

### 5.4 パラメータ・コンパイラ（差別化機能）

利用者が入力する人間向けの項目と、最終URLの機械向けパラメータを分離する。

例として「媒体=メール、施策=秋セール、配信月=2026年9月」を入力すると、プロファイルの規則により以下を同時生成できる。

```text
utm_source=newsletter
utm_medium=email
utm_campaign=202609_autumn_sale
cid=email|202609|autumn_sale
```

これにより、利用者はベンダーごとのコード体系を暗記せず、組織が定めた正しい形式を使える。

## 6. 主要画面と体験

### A. 匿名ビルダー（ホーム）

1. 「新規作成」またはURL貼り付けから開始する。
2. プロファイルを選ぶ。選ばなければ汎用のキー・値エディターを表示する。
3. パラメータを入力、候補検索、任意行追加、URL解析結果の編集を行う。
4. 右側または上部のプレビューで、完成URLと検査結果を常時確認する。
5. コピー、CSV出力、ローカル保存、JSONバックアップを実行する。
6. 共有やクラウド保存を押した時だけ、ログインの選択肢を表示する。

### B. ローカル・ライブラリ

匿名でも、保存したURL・ノート・ローカルプロファイル・最近使った候補を検索・複製・編集できる。データ消失に備え、バックアップ書き出しを目立つ場所に置く。

### C. ログイン後のワークスペース

- 個人スペースと組織スペースを切り替える。
- 組織プロファイル、承認済み候補、キャンペーンマトリクス、共有URLを一覧化する。
- URLの詳細にはノート、コメント、変更履歴、承認状態を表示する。

### D. 管理画面

管理者はプロファイルをノーコードで編集し、候補セット、命名規則、必須項目、公開範囲、承認要否を設定する。変更は即時公開ではなく、下書き・プレビュー・公開の段階を持つ。

## 7. ユーザーストーリー

### P0

- 匿名の利用者として、ログインせずに任意のURLへ任意のパラメータを追加したい。安全なURLをすぐコピーするため。
- 匿名の利用者として、既存URLを貼り付けてパラメータを編集したい。URLの他のクエリやハッシュを壊さないため。
- 匿名のマーケターとして、GA4またはAdobe用の雛形を選びたい。キーや値の形式を毎回調べずに済むため。
- 匿名の利用者として、ブラウザ内にURLとメモを保存し、後から編集・CSV出力したい。アカウントを作らずに継続利用するため。
- ログイン利用者として、匿名時のローカルデータを自分のクラウド領域へ移行したい。端末をまたいで使うため。

### P1

- 組織管理者として、候補・必須項目・命名規則を含むプロファイルを作りたい。全員の計測データを統一するため。
- 組織メンバーとして、承認済みプロファイルでURLを作り、チームに共有したい。誤った計測ルールを使わないため。
- 組織メンバーとして、URLにノートとコメントを残したい。制作意図や修正理由を後から確認するため。
- マーケターとして、複数媒体・複数クリエイティブのURLを一括生成したい。コピペによる誤りを減らすため。

### P2

- 管理者として、URL公開前の承認を必須にしたい。重要施策の計測事故を防ぐため。
- 利用者として、リンク切れやリダイレクト先を検査したい。配信前にリンク品質を確認するため。

## 8. 要件と受入条件

### P0: 匿名で完結する汎用ビルダー

| 要件 | 受入条件 |
|---|---|
| 汎用キー・値編集 | 任意のキーを追加・編集・削除・並び替えできる。未知の既存キーを消さない。 |
| URL解析 | URL貼り付け時に、パス・クエリ・ハッシュを表示し、重複キーも検出する。 |
| 安全な生成 | Given 既存クエリとハッシュを持つURL、When パラメータを追加、Then 既存要素を保持して正しいURLを生成する。 |
| プロファイル | GA4、Adobe、汎用のスタータープロファイルを提供し、利用者は切替・複製できる。 |
| ローカル保存 | URL、ノート、ローカルプロファイルを端末内に保存し、検索・編集・削除・JSONバックアップ／復元できる。 |
| 検査 | 不正URL、空キー、重複、規則違反、URL長、個人情報らしき値を明確に警告する。警告はコピーを不用意に妨げず、危険度で扱いを分ける。 |
| アクセシビリティ | キーボードのみで主要操作を完了でき、ラベル・エラー・通知を支援技術へ伝える。 |

### P1: ログインとチーム運用

| 要件 | 受入条件 |
|---|---|
| 認証 | メールまたは企業認証でログインできる。ログインしない利用者をビルダーから追い出さない。 |
| データ移行 | Given ローカル保存がある匿名利用者、When ログイン後に移行を選択、Then 対象データを確認してクラウドへ複製できる。 |
| ワークスペース | 個人と組織の保存領域を分け、組織外の利用者はデータを読めない。 |
| 役割 | `owner`、`admin`、`editor`、`viewer` を実装する。管理者のみが組織プロファイルを公開・変更できる。 |
| 共有・編集 | URLまたはマトリクスをメンバーと共有し、編集権限を選べる。変更履歴に操作者・時刻・差分が残る。 |
| 組織ルール | 管理者はパラメータ定義、候補、正規化、禁止値、必須値、公開版を管理できる。 |

### P2: 高度な統制・自動化

- 承認フロー、コメント、期限切れ通知
- 動的トークン（例: `{{campaign.name}}`）と広告媒体向けテンプレート
- 一括生成、CSV／スプレッドシート連携、API
- リンクのHTTP到達性・リダイレクト・URL長を確認するサーバー側検査
- ブラウザ拡張、ブックマークレット、制作ツール連携

## 9. データ設計

| エンティティ | 主な属性 | 匿名 | ログイン後 |
|---|---|---:|---:|
| `profile` | 名前、項目定義、規則、版、所有者 | ローカル | 個人／組織 |
| `parameter_definition` | キー、型、候補、必須、変換、説明、機密性 | ローカル | 個人／組織 |
| `url_document` | 元URL、パラメータ、生成URL、ノート、状態 | ローカル | 個人／組織 |
| `campaign_matrix` | 軸、生成ルール、行、ノート | ローカル | 個人／組織 |
| `workspace` | 組織名、設定、メンバー | なし | 組織 |
| `membership` | ユーザー、役割、招待状態 | なし | 組織 |
| `revision` | 対象、変更前後、操作者、日時 | 任意のローカル履歴 | 監査ログ |

パラメータ値は文字列だけでなく、`text`、`select`、`multi-select`、`date`、`number`、`boolean`、`token`、`computed` を許容する。`computed` は他の入力をテンプレート規則で結合して最終値を作る。

## 10. セキュリティ・プライバシー

- 匿名利用で入力値をサーバー送信しない。製品分析を行う場合も、URL本体・クエリ値を収集しない。
- URLに個人情報・認証情報・署名付きトークンを含めないよう警告する。警告対象をログや分析基盤に保存しない。
- ログイン後の組織データは、ワークスペース単位の認可をサーバー側で必ず検証する。
- 共有リンクは有効期限、閲覧／編集権限、無効化を持つ。機密プロファイルはリンク共有を禁止できる。
- ノートには機密情報を記載しないよう明示し、将来的には組織ポリシーによる検査を追加する。

## 11. 技術方針と公開形態

### 現行版

現行のGitHub Pages版は、匿名ビルダーの配布先として維持できる。ローカル保存のみであれば静的ホスティングで十分である。

### 次期版

認証、クラウド保存、共有編集、組織認可にはバックエンドが必要となる。次期版は以下を分離する。

- フロントエンド: 静的配信可能なSPA。匿名モードはバックエンド不達でも動作する。
- 認証・データAPI: ユーザー、ワークスペース、権限、共有、履歴を提供する。
- データベース: 組織／個人単位で厳格にアクセス制御する。
- 非同期処理: リンク検査、通知、一括インポートなど、URL値を必要以上に永続化しないジョブ。

GitHub Pagesだけではログイン後の機能を安全に提供できないため、公開版の匿名SPAと、認証・APIを持つアプリケーション基盤を分ける。プロファイル・URL文書のデータ形式を共通にして、匿名データの移行を可能にする。

## 12. 成功指標

| 指標 | 成功基準 | 測定方法 |
|---|---|---|
| 匿名の初回完了率 | 公開後30日で70%以上 | URL生成・コピーの匿名集計（入力値は収集しない） |
| 初回生成までの時間 | 中央値90秒以下 | 匿名集計 |
| URL検査での修正率 | 警告表示後に30%以上が修正される | 匿名集計または明示同意の分析 |
| ローカル継続利用 | 30日以内に保存済みURLを再利用する割合25%以上 | 端末内の任意集計、またはログイン利用者集計 |
| チーム導入 | ログイン機能公開後90日で、組織プロファイルを1つ以上公開した組織30%以上 | サーバー集計 |
| 計測事故 | 導入組織で命名規則違反・重複URLの報告を減らす | 導入前後のヒアリング |

## 13. 段階的な実装計画

### フェーズ1: 匿名汎用ビルダー

現行アプリを置き換える。汎用キー・値編集、URL解析、スタータープロファイル、ローカルノート・プロファイル、CSV／JSON、検査を実装する。ログインは実装しない。

### フェーズ2: 個人アカウントと同期

認証、個人クラウド保存、ローカルデータ移行、端末間同期を実装する。匿名モードは維持する。

### フェーズ3: 組織ワークスペース

組織プロファイル、候補マスタ、役割、共有、共同編集、履歴を実装する。

### フェーズ4: 統制と自動化

承認、キャンペーンマトリクス、リンク品質検査、外部連携、APIを実装する。

## 14. 今回は作らないもの

- URL短縮サービス: 短縮URLの運用・悪用対策は別プロダクトとして扱う。
- 広告プラットフォームへの直接配信・予算操作: 認証範囲と責務が大きく、URL生成の中核ではない。
- 利用者のURL内容を使った広告プロファイリング: プライバシー原則に反する。
- リアルタイム共同編集: まずは共有・履歴・楽観ロックで十分であり、複雑な同期は後段とする。
- すべてのベンダー仕様を標準で内蔵: スターターは提供するが、組織カスタマイズを優先する。

## 15. 実装開始前の確認事項

| 質問 | 決定者 | 重要度 |
|---|---|---|
| 最初に標準提供するプロファイルと値の候補は何か | プロダクト／計測担当 | 高 |
| `cid` などAdobeの追跡コード規則は、対象組織で既に決まっているか | 計測担当 | 高 |
| クラウド保存に含めてよいURL・ノートのデータ分類は何か | セキュリティ／法務 | 高 |
| ログイン方法（メール、企業SSO、招待制）の優先順位は何か | プロダクト／IT | 中 |
| 共有リンクは組織外に許可するか | 管理者／法務 | 中 |
| URL到達性検査のために外部URLへアクセスすることを許可するか | セキュリティ | 中 |

## 16. 次に実装する範囲

次の開発単位は **フェーズ1** とする。具体的には「匿名のまま、GA4・Adobe・カスタムを含む任意パラメータURLを安全に作成・解析・ローカル保存・ノート・CSV出力できること」を完成条件とする。

ログイン・共有・組織設定は、そのデータモデルを前提にフェーズ2以降で実装する。これにより、アカウント作成を利用開始の条件にせず、将来のチーム利用にも拡張できる。
